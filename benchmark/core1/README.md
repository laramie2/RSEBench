# RSEBench Core-1

Core-1 is the executable validation slice of RSEBench. Its four peer domains
are evaluated together; SkillLearnBench is a skill-native diagnostic domain,
not a replacement for task benchmarks.

| Domain | Benchmark | Reference baseline |
|---|---|---|
| Spreadsheet | SpreadsheetBench-Verified | SkillOpt |
| Document QA | OfficeQA | SkillOpt |
| Skill Learning | SkillLearnBench | Self-Feedback; Teacher-Feedback for N4 |
| Interactive | WebShop | SkillAdaptor |

Mathematics is not part of the active Core-1 matrix.

## Noise stages

The four stage names describe **where evolution evidence is corrupted**. They
are mutually exclusive arms, not a Cartesian product.

| Stage | Fixed benchmark artifact | Runtime boundary |
|---|---|---|
| N1 task context | clean/noisy task pair | before the first action |
| N2 environment evidence | clean/noisy artifact or ranked evidence view | during execution |
| N3 stored trajectory | selector/operator/seed/spec | after rollout and reward, before reflection |
| N4 update feedback | selector/operator/seed/spec | after feedback, before skill update |

N1/N2 are fully materialized under `static_data/` and referenced by the paired
split manifests. N3/N4 cannot be universal fixed model-output files because
their input is generated by the evaluated method. Instead, the release fixes
the mutation program under `runtime/`; each run writes the resulting datum as
an audited `input.json`, `output.json`, and `audit.json` replay pack.

Split manifests are machine-portable. Artifact locators use
`rsebench-data://`, `rsebench-methods://`, and `rsebench-project://` roots;
paired runners resolve them from `RSEBENCH_DATA_ROOT`,
`RSEBENCH_METHODS_ROOT`, and the installed project root immediately before a
native baseline executes. Locator strings are excluded from task content
hashes; referenced artifact bytes are covered by their content hash instead.

## Core-1 operator matrix

| Benchmark | N1 | N2 | N3 | N4 |
|---|---|---|---|---|
| SpreadsheetBench-Verified | append a plausible erroneous handover that changes one task constraint | add an unlabeled stale semantic sheet while preserving every original sheet | omit one tagged workbook-write event, preserving save/final/reward | replace blamed sheet/range with a same-shape decoy, preserving verifier score |
| OfficeQA | append a prior analyst derivation that changes one observed period/unit/aggregation axis | place a real same-topic, conflicting-period source with the oracle in top-3 | omit one oracle-source open/read event after the answer rollout | replace source/period/unit attribution before SkillOpt revision |
| SkillLearnBench | append an instance-specific brittle workflow to acquisition instance 1 | add a competing stale resource while keeping the official environment and hidden tests | omit one artifact-producing filesystem event from the revision trace | replace the self/teacher diagnosis target before rewriting the reusable skill |
| WebShop | name a real near-match product that violates exactly one hard constraint | promote that real near-match while retaining a valid target in top-10 | omit one required-option or query-refinement action-observation event | replace the localized actionable fault step before SkillAdaptor linking/revision |

Every Core-1 operator has mutation budget one. Failure to find its declared
target is recorded as `applicable=false`; no operator falls back to another
noise type.

## Reproduction

Materialize all four domains:

```bash
python scripts/build_core1_splits.py --domain all
```

Set `RSEBENCH_DATA_ROOT` and `RSEBENCH_METHODS_ROOT` when the downloaded data
or baseline checkouts are not in the default shared-project locations.

Run one bounded validation cell with DeepSeek V4 Flash (thinking disabled by
the provider adapter):

```bash
python scripts/run_core1_screen.py \
  --domain document --stage N4 \
  --output-dir outputs/runs/core1-screen-document-n4
```

The comparison always starts from one seed skill, evolves on the paired clean
and noisy training/validation data, and evaluates both resulting artifacts on
the same untouched clean test split. A candidate noise cell must also show
non-degrading clean evolution, different update evidence/artifacts, complete
token accounting, and no systemic harness failure.

See `docs/core1-runtime-evidence-interface.md` for integration of a new
baseline and `docs/reports/core1-validation-status.md` for pilot results.
